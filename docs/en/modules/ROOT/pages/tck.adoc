== Prerequisites

The artefact `org.eclipse.microprofile.metrics:microprofile-metrics-api-tck:5.1.1` is available on Maven Central. The runner first installs the required Dirac modules in the local M2, then runs the standalone `dirac-tck` POM.

[source,bash]
----
sdk env                                              # Java 25 + Maven 3.9.16
./mvnw -ntp install -DskipTests                      # full reactor build
----

== Running the runner

The script `run-official-tck-mp-metrics-5.1.sh` at the repository root orchestrates every variant.

[source,bash]
----
# Smoke test — DiracTckSmokeTest, no Arquillian
./run-official-tck-mp-metrics-5.1.sh

# Full suite — JUnit 4/Arquillian, tck-official profile
./run-official-tck-mp-metrics-5.1.sh all

# Targeted test — tck-official profile + -Dtest=
./run-official-tck-mp-metrics-5.1.sh -Dtest=CounterTest
----

The runner installs `dirac-api`, `dirac-core`, `dirac-cdi-vauban` in the local M2 (step 1), then invokes the standalone `dirac-tck` POM with the requested profile (step 2). The summary report lands in `dirac-tck/target/tck-report.txt`. Direct invocation without the script:

[source,bash]
----
./mvnw -f dirac-tck/pom.xml -Psmoke test             # smoke
./mvnw -f dirac-tck/pom.xml -Ptck-official test      # full suite
----

== Runner architecture

In this release `dirac-tck` is a **standalone out-of-reactor POM** (Model 4.0.0, no `<parent>`): a plain `mvn install` of the reactor neither downloads nor runs anything TCK-related — the module is simply not part of it. The split also decouples the runtime release cycle from the official TCK cycle.

[NOTE]
====
`dirac-tck` sits outside the reactor because ShrinkWrap Maven Resolver 3.3, transitive to the official TCK, could not parse the Model 4.1.0 POMs the workspace used at the time. The MP Metrics api-tck builds its deployments with `addClass`/`addPackage` only (no ShrinkWrap Maven resolver), which is what later let the development line reintegrate the runner in-reactor behind a `tck` Maven profile (post-0.2.0), mirroring the `vidocq-runtime-tck-*` pattern.
====

Stack assembled by the runner:

[cols="1,3"]
|===
| Layer | Component

| Spec
| `microprofile-metrics-api` 5.1.1, `jakarta.enterprise.cdi-api` 4.1, `jakarta.interceptor-api` 2.2, `jakarta.annotation-api` 3.0, `jakarta.ws.rs-api` 4.0

| Metrics implementation
| `dirac-api` + `dirac-core` + `dirac-cdi-vauban` + `dirac-rest`

| CDI container
| Vauban (`io.vidocq.vauban.core`) embedded

| Arquillian container
| Dirac container that deploys the archive and exposes `/metrics` via Cassini + Chappe

| HTTP transport
| Chappe (`io.vidocq.chappe.http`)

| Test framework
| JUnit 4 + Arquillian (`surefire-junit4` provider) — the MP Metrics api-tck is JUnit-based, not TestNG
|===

Arquillian configuration in `dirac-tck/src/test/resources/arquillian.xml`. Current smoke test: `dirac-tck/src/test/java/io/vidocq/dirac/tck/DiracTckSmokeTest.java`.

== jlink smoke (M9)

The jlink smoke validates that the whole Dirac stack can be assembled into a Java native image without an automatic module lacking a canonical name. The blocker is lifted by `dirac-mp-metrics-api`, which repackages the MP Metrics spec with an explicit `module-info.class` (`module microprofile.metrics.api { exports ...; }`).

[source,bash]
----
./run-jlink-smoke.sh           # build + jlink + dirac-image-smoke image
./run-jlink-smoke-ci.sh        # blocking CI wrapper
./mvnw -ntp -N -Pjlink-smoke verify
----

Details in link:{repo-dirac}/src/branch/main/JLINK.md[JLINK.md].

== Quality contract

Any structural modification of `dirac-core`, `dirac-cdi-vauban` or `dirac-rest` must preserve the 127/127 TCK score before merge. A TCK regression is a CI-level blocker: the PR does not pass. Any excluded test (if any) must be justified in link:{repo-dirac}/src/branch/main/TCK.md[TCK.md].
